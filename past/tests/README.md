# テストケース

## 使い方
```bash
python3 your_solution.py < case01_revival_input.txt | diff - case01_revival_expected.txt
```
diff が空なら一致（正解）。

| ケース | 狙い |
|---|---|
| case01_revival | 提供サンプル。取消で発送枠が戻り、後続注文が受理される |
| case02_multi_item | 複数商品の注文。1種でも超過なら全体を拒否、枠も予約しない |
| case03_multi_date | 複数発送日が干渉しないこと。SHIP の注文番号が辞書順 |
| case04_boundary | 容量ちょうど(=M)は受理、+1で拒否。同一発送日への積み上げ |
| case05_mixed | 取消→再注文→発送、複数商品の混在、別発送日の発送 |

## 確認ポイント（よくあるバグ）
- 受理失敗した注文を保存・予約していないか
- 発送枠を発送日ごとに区別しているか
- 複数商品で出力が重複していないか
- SHIP の件数が「発送日が一致する注文数」になっているか
- SHIP 後に注文を消し込んでいるか（重複発送しないか）
