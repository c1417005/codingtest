# 通販サイト注文管理システム — 要件定義

## 概要

通販サイトのシステムを作成する。通販サイトでは N 種類の商品を取り扱っており、**商品番号**によって識別される。i 番目の商品には、商品番号 A_i が割り当てられている (1 ≤ i ≤ N)。

基本実装では、利用者は以下の 2 種類の操作を行う。

- **注文**: 商品から 1 つ以上を選んで注文する。注文日の翌日から D 日後までの範囲で**発送日**を指定する。注文は**注文番号**によって識別される。1 つの注文について、1 種類の商品を複数個注文することもあれば、複数種類の商品を注文することもある。
- **注文の取り消し**: 発送前の注文について、注文の取り消しを行う。複数個の商品が注文されていた場合、全ての商品の注文を取り消す。

通販サイトには**発送可能数 M** が存在し、各商品について 1 日に最大で M 個の商品を発送する。利用者が注文した時には、指定された発送日に発送が可能かを判定する。注文によって、指定された日の発送数が発送可能数を超えるような商品が 1 種類でも存在する場合、注文を受理しない。また、注文がキャンセルされた時、その注文が与えた発送数への影響を元に戻し、戻した分新たな注文を受理できるようにする（この操作によって過去に破棄された注文が遡って受理されることはない）。注文が受理された後、キャンセルされることなく発送日を迎えた注文について、通販サイトは商品を発送する。

---

## 入力形式

### 日時のフォーマット

- **日付**: `yyyy-MM-dd` 形式
  - `yyyy`: 西暦の年。本問題においては全て `yyyy=2022`
  - `MM`: 月（01〜12、2 桁に満たない場合は左ゼロ埋め）
  - `dd`: 日（01〜31、2 桁に満たない場合は左ゼロ埋め）。月によって最大値は異なる（例: MM=03 の場合、dd の最大値は 31）
- **時刻**: `HH:mm:ss` 形式
  - `HH`: 24 時間表記（00〜23、左ゼロ埋め）
  - `mm`: 分（00〜59、左ゼロ埋め）
  - `ss`: 秒（00〜59、左ゼロ埋め）
- **日時**: 日付と時刻を文字 `T` で連結した `yyyy-MM-ddTHH:mm:ss` 形式
  - 例: 2022年12月3日4時56分7秒 → `2022-12-03T04:56:07`

### 共通事項

- プログラムに与えられる入力は、標準入力を介して行われる
- 各行の末尾には改行コード `\n` が付与される（最終行にも付与）
- 各行で入力される文字列は、単一の半角スペースによって区切られている
- 入力は、通販サイトの情報と Q 個のクエリから構成される
  - 1 行目から 4 行目: 通販サイトの情報
  - 5 行目以降: 時系列順に Q 個のクエリ
  - クエリの発行時間 T について、T_i < T_j が保証される

### 通販サイト情報（1〜4 行目）

```
N M D
A_1 ... A_N
H_1 ... H_7
Q
```

| パラメータ | 説明 | 制約 |
|---|---|---|
| N | 商品の種類数 | 1 以上 20 以下の整数 |
| M | 各商品の 1 日の発送可能数 | 1 以上 100 以下の整数 |
| D | 発送日と注文日の差として許容される最大日数 | 1 以上 30 以下の整数 |
| A_i | 各商品の商品番号 | 英大文字アルファベット、長さ 5。全て相違する |
| H_i | 各曜日の発送フラグ（日, 月, 火, 水, 木, 金, 土の順） | 0 または 1 |
| Q | クエリの個数 | 1 以上 1000 以下の整数 |

- H_i = 0 のとき: その曜日の発送可能数は 0
- H_i = 1 のとき: その曜日の発送可能数は M
- **基本実装においては、H_i = 1 (1 ≤ i ≤ 7) が保証される**

## クエリ

### 1. 注文クエリ（ORDER）— 基本実装・応用実装

#### 入力形式

```
ORDER T
B C K
X_1 Y_1
...
X_K Y_K
```

| パラメータ | 説明 | 制約 |
|---|---|---|
| T | クエリが発行された日時 | `yyyy-MM-ddTHH:mm:ss` |
| B | 注文番号 | 英大文字アルファベット、長さ 10。異なる注文クエリで同じ番号は与えられない |
| C | 発送日の日付 | T の日付の翌日から T の日付の D 日後までの範囲 |
| K | 注文する商品の種類数 | 1 以上 N 以下の整数 |
| X_i | 注文する i 種類目の商品番号 | 通販サイトに存在する商品番号 |
| Y_i | 注文する i 種類目の商品の個数 | 1 以上 100 以下の整数 |

#### 出力形式

- **受理する場合:**
  ```
  T Ordered B
  ```

- **受理しない場合（発送可能数超過）:**
  ```
  T Ordered B Error: the number of available shipments has been exceeded.
  ```

#### 判定ルール

- 注文は、通販サイトの判定を通過したときのみに受理される（概要に準ずる）
- 受理されなかった注文は破棄される

---

### 2. 注文取り消しクエリ（CANCEL）— 基本実装・応用実装

#### 入力形式

```
CANCEL T
B
```

| パラメータ | 説明 | 制約 |
|---|---|---|
| T | クエリが発行された日時 | `yyyy-MM-ddTHH:mm:ss` |
| B | 注文番号 | 受理済み・未発送・未取消の注文のみ |

- 受理されなかった注文、取り消された注文、発送済みの注文について取り消しクエリが発行されることはない

#### 出力形式

```
T Canceled B
```

#### 取り消し時の処理

- 注文が取り消された時、その注文で指定していた発送日に発送する商品の数は、注文していた分だけ減少する
- 各日付に発送する商品の個数は、注文を受理するかの判定に用いられるため注意すること

---

### 3. 発送クエリ（SHIP）— 基本実装・応用実装

#### 入力形式

```
SHIP T
```

| パラメータ | 説明 | 制約 |
|---|---|---|
| T | クエリが発行された日時 | 時刻が `00:00:00` であることが保証される |

- 発送クエリは各日付のクエリにおいて、最も早く発行される
- T の日付に発送する商品が存在するとき、発送クエリは必ず発行される
- T の日付に発送する商品が存在しないとき、発送クエリは発行されない

#### 出力形式

```
T Shipped E Orders
B_1 ... B_E
```

- 1 行目: 日時 T、文字列 `Shipped`、発送する注文の数 E、文字列 `Orders` を半角スペース区切り
- 2 行目: 発送する注文番号 B_i (1 ≤ i ≤ E) を半角スペース区切り
  - **注文番号 B_i は文字列の辞書順に出力せよ**

---

## 業務ルールまとめ

### 注文

- 商品の注文は、通販サイトの判定を通過したときのみに受理される
- 受理されなかった注文は破棄される

### 注文の取り消し

- 注文が取り消された時、その注文で指定していた発送日に発送する商品の数は、注文していた分だけ減少する
- 各日付に発送する商品の個数は、注文を受理するかの判定に用いられる

### 商品の発送

- 商品の発送は、注文ごとに行われる
- 日付が変わると同時（00:00:00）に商品が発送される
- 発送日を迎えた注文に対して、発送前に注文が取り消されること（基本実装）や、発送日が変更されること（応用実装）はない

---

## 出力形式

- 各クエリに対して、問題文で指定された内容をクエリが与えられた順に標準出力に出力せよ
- 各行の末尾には改行コード `\n` を付与せよ（最終行にも付与）
- 各行で出力する文字列を区切る場合は、単一の半角スペースを用いよ
- 全てのクエリに対する処理を終えたら、終了コード `0` でプログラムを終了せよ
